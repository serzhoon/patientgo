# Инструкция по развёртыванию

Здесь два развёртывания:
1. **Фронтенд** → GitHub Pages (бесплатно).
2. **Бэкенд + база данных** → Docker на сервере SberCloud.

Команды даны построчно. Выполняйте по порядку.

---

## Часть 1. Заливка проекта на GitHub

> Предполагается, что у вас уже есть аккаунт на github.com и установлен Git.
> Проверить Git: в терминале выполните `git --version`.

### 1.1. Создать репозиторий на GitHub

1. Зайдите на github.com → нажмите **New** (новый репозиторий).
2. Имя: например `clinic-appointments`.
3. **Не** добавляйте README/gitignore (они у нас уже есть).
4. Создайте — GitHub покажет адрес вида
   `https://github.com/ВАШ_ЛОГИН/clinic-appointments.git`.

### 1.2. Залить код с двумя ветками (main + develop)

Откройте терминал в папке проекта `clinic-appointments` и выполняйте по строке:

```bash
git init
git add .
git commit -m "Initial commit: структура проекта"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/clinic-appointments.git
git push -u origin main

# создаём вторую ветку develop
git checkout -b develop
git push -u origin develop
```

## Часть 2. Фронтенд на GitHub Pages

GitHub Pages показывает только статические файлы. Наш фронтенд — как раз такой.

### Вариант А (просто): Pages из папки

1. В репозитории: **Settings → Pages**.
2. **Source**: Deploy from a branch.
3. Branch: `main`, папка `/frontend` (если выбор папки недоступен — см. вариант Б).
4. Сохраните. Через пару минут сайт будет по адресу
   `https://ВАШ_ЛОГИН.github.io/clinic-appointments/`.

### Вариант Б: если Pages не даёт выбрать папку /frontend

GitHub Pages иногда позволяет только корень или `/docs`. Тогда:
- Либо перенесите содержимое `frontend/` в отдельную ветку `gh-pages`,
- Либо создайте отдельный репозиторий только для фронтенда.

Самый простой путь — ветка `gh-pages` только с файлами фронтенда:

```bash
git subtree push --prefix frontend origin gh-pages
```

Затем в **Settings → Pages** выберите ветку `gh-pages`.

### 2.1. ВАЖНО: указать адрес бэкенда

Пока бэкенд не развёрнут, фронт на Pages не сможет получить данные.
После развёртывания бэкенда (Часть 3) откройте `frontend/config.js` и впишите
адрес вашего сервера:

```javascript
const API_BASE = 'http://АДРЕС_ВАШЕГО_СЕРВЕРА:3000/api';
```

Закоммитьте и запушьте изменение — Pages обновится сам.

## Часть 3. Бэкенд + MySQL в Docker на SberCloud

### 3.1. Создать сервер

1. В SberCloud создайте облачный сервер (ECS) с Ubuntu.
2. При создании откройте порты (Security Group): `22` (SSH), `3000` (API).
3. Запомните публичный IP-адрес сервера.

### 3.2. Подключиться к серверу

С вашего компьютера:

```bash
ssh root@ПУБЛИЧНЫЙ_IP
```

(или пользователь, который дал SberCloud, например `ubuntu`).

### 3.3. Установить Docker на сервере

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-plugin git
sudo systemctl enable --now docker
```

### 3.4. Скачать проект и запустить

```bash
git clone https://github.com/ВАШ_ЛОГИН/clinic-appointments.git
cd clinic-appointments
sudo docker compose up --build -d
```

Флаг `-d` запускает в фоне.

### 3.5. Проверить

В браузере откройте:

```
http://ПУБЛИЧНЫЙ_IP:3000/api/health
```

Должно вернуть `{"status":"ok",...}`. Значит, бэкенд работает.

### 3.6. Связать фронт и бэк

Вернитесь к шагу 2.1 — впишите `http://ПУБЛИЧНЫЙ_IP:3000/api` в `config.js`,
запушьте. Теперь сайт на GitHub Pages работает с вашим сервером.

> **Замечание про HTTPS.** GitHub Pages работает по `https`, а бэкенд по `http`
> браузер может блокировать («mixed content»). Для зачёта обычно достаточно
> показать работу. Для «чистого» решения позже можно повесить домен и сертификат
> (например, через Nginx + Let's Encrypt), но это не обязательно для курсовой.

## Полезные команды Docker (на сервере)

```bash
sudo docker compose ps          # какие контейнеры запущены
sudo docker compose logs -f     # смотреть логи
sudo docker compose down        # остановить
sudo docker compose up -d       # снова запустить
```

## Рекомендуемая история коммитов

Чтобы история выглядела как поэтапная разработка, коммитьте примерно так
(в ветке `develop`, затем слияния в `main`):

```
1.  Initial commit: структура проекта
2.  Добавлена схема базы данных MySQL
3.  Настроено подключение к базе данных
4.  Реализована регистрация и вход по паролю
5.  Добавлен middleware проверки токена и роли
6.  Реализован контроллер врачей
7.  Реализован контроллер записей на приём
8.  Подключены маршруты API
9.  Добавлен скрипт создания администратора
10. Свёрстана страница входа и регистрации
11. Свёрстана форма записи на приём
12. Реализована логика фронтенда (fetch к API)
13. Добавлено отображение и отмена записей
14. Добавлен Dockerfile для бэкенда
15. Добавлен docker-compose (backend + mysql)
16. Написан README и инструкция по развёртыванию
17. Настроен деплой фронтенда на GitHub Pages
```
